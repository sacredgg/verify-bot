# Verify Bot

Бот верификации для Discord: защищает сервер от рейдов и ботов.

Новичок заходит на сервер → не имеет доступа к каналам → нажимает кнопку
«Пройти верификацию» → получает роль и доступ.

## Как это работает

1. Админ настраивает роль и канал.
2. `/setup` публикует в канал сообщение с кнопкой верификации.
3. При заходе участника бот присылает ему в личку ссылку на канал верификации.
4. Новичок жмёт кнопку — бот выдаёт роль.

Чтобы кнопка реально защищала сервер, скройте каналы от роли `@everyone`
и откройте их только для роли верификации (Настройки канала → Права доступа:
`@everyone` → Смотреть каналы: ❌, роль верификации → Смотреть каналы: ✅).

## Команды

| Команда | Права | Описание |
|---|---|---|
| `/setrole @роль` | админы | Роль, выдаваемая после верификации |
| `/setchannel #канал` | админы | Канал для сообщения верификации |
| `/setup [#канал]` | админы | Опубликовать сообщение с кнопкой |

## Анти-рейд

В переменной окружения `NEW_ACCOUNT_DAYS` можно указать минимальный возраст
аккаунта (в днях). Участники с более новыми аккаунтами автоматически кикаются.
`0` (по умолчанию) — выключено.

## Настройка бота в Discord

1. https://discord.com/developers/applications → создайте приложение → **Bot** → **Reset Token**.
2. Включите **Privileged Gateway Intent** → `SERVER MEMBERS INTENT` (обязательно для верификации).
3. OAuth2 → URL Generator:
   - Scope: `bot`, `applications.commands`
   - Permissions: `Send Messages`, `Embed Links`, `Use Slash Commands`, `Manage Roles`, `Kick Members`
   - Откройте ссылку и добавьте бота на сервер.

## Запуск локально

```bash
pip install -r requirements.txt
cp .env.example .env   # вписать DISCORD_TOKEN
python bot.py
```

## Деплой на Railway (24/7)

1. Заливайте код в GitHub-репозиторий.
2. railway.com → **New Project** → **Deploy from GitHub repo**.
3. В **Variables** укажите `DISCORD_TOKEN` (и при желании `NEW_ACCOUNT_DAYS`).
4. Сгенерируйте домен сервиса (**Settings → Networking → Generate Domain**) —
   бот сам его пингует, чтобы Railway не «усыплял» сервис.

## Хранение данных

- Роль и канал хранятся в `config.json` (переменная `CONFIG_PATH` может менять путь).
